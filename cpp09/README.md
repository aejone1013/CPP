햣 ## C++ Module 09 요약 (ex00, ex01, ex02 개요)

이 문서는 42 C++ Module 09 각 과제의 핵심 요구사항과 주의점을 정리한 README입니다. 현재 레포에는 `ex00`, `ex01`이 포함되어 있으며, 일반적으로 `ex02`도 출제되므로 개요를 함께 기재합니다.

### ex00: BitcoinExchange
- **목표**: 입력 파일의 날짜·수량을 비트코인 가격 데이터(`data.csv`)와 매칭해 결과 출력.
- **핵심 구현**
  - `data.csv` → `std::map<std::string,double>`에 `date -> price` 적재.
  - 입력 파일 라인 형식: `YYYY-MM-DD | value` (공백 트림 필수).
  - 날짜가 정확히 없으면 `map.lower_bound(date)`로 가장 가까운 "이전" 날짜 사용.
- **유효성/에러 처리**
  - 날짜: 형식(YYYY-MM-DD), 숫자 여부, 월/일 범위(+윤년) 검증.
  - 값: 실수 파싱 실패 → "Error: bad input => ..."; 음수 → "Error: not a positive number."; 1000 초과 → "Error: too large a number.".
  - 파일 열기 실패, 형식 오류 메시지는 과제 포맷을 정확히 맞출 것.
- **출력 예시**
  - `YYYY-MM-DD => value = result`
- **주의/함정**
  - CSV/입력 모두 첫 줄 헤더 스킵.
  - `lower_bound`가 `begin()`이면 과거 데이터 없음 처리(예외/메시지).
  - 파싱 시 공백/탭 트림, `isdigit` 사용 시 `unsigned char` 캐스팅.

#### ex00 빠른 테스트 예시
- 정상: `2011-01-03 | 2`
- 오류: `2011-02-29 | 1`(잘못된 날짜), `2011-01-03 | -1`(음수), `2011-01-03 | 2001`(초과), 포맷 불일치 라인

### ex01: RPN (Reverse Polish Notation)
- **목표**: 후위 표기식 계산기 구현. 공백으로 구분된 토큰(한 글자)만 처리.
- **핵심 로직**
  - `std::stack<int>` 사용.
  - 숫자(0~9) → push, 연산자(`+ - * /`) → 피연산자 2개 pop 후 계산·push.
  - 종료 시 스택에 값이 하나만 남아야 함.
- **유효성/에러 처리**
  - 토큰이 한 글자가 아니면 에러.
  - 피연산자 개수 부족 에러.
  - 0으로 나누기 에러.
  - 괄호·알파벳 등 비허용 문자 에러.
  - 과제에 따라 에러 메시지를 "Error"로 고정하는 경우가 많음(명세 확인).
- **주의/함정**
  - 두 자리 숫자 미허용(기본 규칙). 필요 시 명세 재확인.
  - 연산 순서 주의: `b` 먼저 pop, 그다음 `a`, 계산은 `a op b`.

#### ex01 빠른 테스트 예시
- 정상: `"8 9 * 9 - 9 - 9 - 4 - 1 +"`, `"3 4 +"`, `"5 1 2 + 4 * + 3 -"`
- 오류: `"12 +"`(두 자리), `"3 +"`(피연산자 부족), 괄호 포함

### ex02: PmergeMe (일반적으로 포함되는 과제)
- **목표**: Ford–Johnson(merge-insert) 정렬을 `std::vector`, `std::deque`로 각각 구현하고 성능 비교 출력.
- **입력/출력**
  - 인자로 양의 정수 시퀀스 입력. 음수/비숫자/오버플로 검증.
  - 정렬 전/후 시퀀스 출력 + 각 컨테이너의 처리 시간(ms 또는 μs) 출력.
- **알고리즘 핵심**
  - 페어링 → 큰 값들로 기초 정렬 → 작은 값들을 이진 삽입으로 병합.
  - 삽입 순서는 Jacobsthal 수열 기반(명세 참고).
  - 목표 시간복잡도: O(n log n) 수준. `vector` vs `deque` 차이 관찰.
- **구현 포인트**
  - 파싱·검증 분리, 같은 로직으로 두 컨테이너 처리.
  - `std::lower_bound` 등 이진 삽입 활용.
  - 입력이 매우 적을 때(1~2개)의 엣지 케이스 처리.

### 공통 제출 팁
- **컴파일 플래그**: `-Wall -Wextra -Werror -std=c++98`
- **입출력 포맷**: 과제 요구 문구·띄어쓰기·마침표까지 정확히 일치.
- **예외 처리**: 불필요한 try/catch 남발 지양, 메시지 일관성 유지.
- **성능/코드 품질**: 불필요한 복사 최소화, `const&` 활용, I/O 버퍼링.
- **테스트 권장**: 경계값·에러 케이스를 포함한 자가 테스트 세트로 검증.
